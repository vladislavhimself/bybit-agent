# Режим Мосбиржи: голова в Германии, ретранслятор в России, связь через Cloudflare

## Почему так

- Бот целиком («голова») работает на немецком сервере: новости, модель Anthropic, решения, Telegram.
  С Anthropic и Telegram он общается напрямую из Германии.
- T-Invest API, ISS Мосбиржи и часть российских изданий не отвечают зарубежным дата-центрам, поэтому
  запросы к российским хостам выполняет ретранслятор на VDS в Москве (FirstVDS, 188.120.245.223).
- Российские сети не пропускают пакеты к адресам нашего немецкого хостера (ни TCP, ни UDP, в обе стороны),
  так что прямой туннель невозможен. Обе стороны держат WebSocket к брокеру на Cloudflare Workers
  (`relay/worker/`, бесплатный тариф), который просто перекладывает сообщения между ними.

```
Германия: bot ──HTTP──> relay/bridge.py ──WS──> Cloudflare Worker (Durable Object)
                                                      │
Москва:   relay/agent.py ─────────────WS──────────────┘ ──> T-Invest / ISS / *.ru
```

## Компоненты

| Где | Что | Запуск |
|---|---|---|
| Cloudflare | `relay/worker/worker.js` — брокер, секрет `RELAY_KEY` | `cd relay/worker && npx wrangler deploy`, `wrangler secret put RELAY_KEY` |
| Германия | `relay/bridge.py` — локальный `POST /fetch` на 127.0.0.1:8082 + WS к брокеру | systemd `relay-bridge` (env из `/opt/bybit-agent/.env`: `RELAY_WS`, `RELAY_KEY`) |
| Германия | бот: `bot/net.py` → `RoutedSession` отправляет российские хосты в мост | `.env`: `RELAY_URL=http://127.0.0.1:8082`, `RELAY_KEY` |
| Москва | `relay/agent.py` — выполняет запросы (только `.ru/.su/moex.com/tbank.ru`), сжимает ответ | systemd `relay-agent` (env `/opt/relay/env`: `RELAY_WS`, `RELAY_KEY`, `RELAY_CA=/opt/relay/ca_bundle.pem`) |

Ключей и токенов на московской машине нет. Брокер не хранит данные, без `RELAY_KEY` отвечает 403.
Статус: `curl -H "X-Relay-Key: …" https://bot-relay.<account>.workers.dev/status` → `{"heads":1,"relays":1}`.

## Особенности

- Российские фильтры режут часть адресов Cloudflare и иногда рвут TLS: агент перебирает все IPv4
  и переподключается с нарастающей паузой; установленное соединение живёт долго.
- Лимит бесплатного тарифа — 100 000 запросов в день; сообщения по WebSocket считаются 20:1, так что
  запас большой. При смене тарифа ничего менять не нужно.
- Без ретранслятора (нет связи) бот не может ни читать котировки, ни ставить ордера: позиции остаются
  под стоп-заявками брокера, бот пишет об ошибках в Telegram не чаще раза в 30 минут.
- Запуск без ретранслятора (с машины в России или из дома): не задавать `RELAY_*` — всё пойдёт напрямую.

## Если что-то не работает

1. `systemctl status relay-agent` на Москве, `systemctl status relay-bridge` на Германии.
2. Статус брокера (см. выше): если `relays: 0`, проблема на московской стороне (сеть/TLS к Cloudflare).
3. Логи: `journalctl -u relay-agent -f`, `journalctl -u relay-bridge -f`, `journalctl -u bybit-agent -f`.
